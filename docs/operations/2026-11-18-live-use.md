# 公開版を使った運用ウォークスルー（2026-11-18）

対象: [AEO Check 公開版](https://rsasaki0109.github.io/ai_search_engine_optimization/)

開発者1名が新しいChromiumプロファイルで、実際の公開版を操作しました。一般利用者のユーザーテストや、AI検索サービスでの引用率測定ではありません。

## 操作した流れ

1. 公開画面で診断方法を確認。
2. GNUの公開ページとrobots.txtを保存し、元URLとファイルを指定して診断。
3. 自分のOSSの公開ドキュメント（lidar_slam）へURLとHTMLを切り替えて診断。
4. JSONとMarkdownを保存し、入力の追跡ができるか確認。
5. 保存した診断JSONをファイル選択の「すべてのファイル」相当で入力し、誤操作への案内を確認。
6. 375px幅でも表示を確認。

保存対象は `https://www.gnu.org/software/`、`https://www.gnu.org/robots.txt`、`https://rsasaki0109.github.io/lidar_slam/index.html`。対象サイトに書き込みは行いませんでした。

## 発見した問題と対応

| 優先度 | 公開版で確認した問題 | 対応 |
| --- | --- | --- |
| 高 | サイトを切り替えてもGNUのrobots.txtが選択されたまま。lidar_slamのrobots.txtを指定していないのに、5ボットすべてが許可と表示された | URLのorigin変更時と診断直前にrobots.txtの対応を確認し、異なるサイトのファイルを解除。未提供は判定不明として表示 |
| 高 | 保存した診断JSONを選んでも「端末内の診断が完了」と表示され、新しい履歴が作られる | 拡張子/MIMEと内容を確認。JSON・空・非HTMLは診断せず、HTMLの保存・選択手順へ案内。htmlへ改名したJSONも拒否 |
| 中 | JSONに入力ファイル名がなく、同じURLのどの保存HTMLを診断したか追いにくい | HTMLとrobots.txtの名前・サイズ・SHA-256を結果・履歴・レポートに保存。旧履歴は情報なしと明示 |
| 中 | 診断入力が最初の画面より下にあり、HTMLの保存方法の説明も短い | Pages版の冒頭を短くし、「HTMLのみ」で保存する手順を明記 |

結果の上部に「保存HTMLのみ」「HTTPヘッダー・取得可否は未確認」「robots.txt未提供・判定不明」を示し、HTML内のインデックス指定とHTTPヘッダーの検証を区別します。SHA-256はファイル識別用で、内容の正しさや取得元の証明ではありません。
